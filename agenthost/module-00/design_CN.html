关键技术考虑 - 有状态设计

先持久化，再安全休眠。

1

启动

解析 Agent ID，并从 Blob 加载其 JSON 状态。

2

执行

处理消息、工具及受治理的模型调用。

3

保存

每次变更后写入对话和工具状态。

4

空闲

逐出、暂停或缩容到零，无需最后一次刷盘。

5

恢复

直接从 Blob 最新的持久化版本恢复。

唯一事实来源： <AGENT_ID>.json 存储于启用版本控制的 Blob Cool 层，不使用独立的 Redis 热缓存。

同一个业务场景，四种执行模式
模式示例问题执行方式 / 证据
DIRECT为一款可维修音箱写三条宣传语。仅调用通用模型；不检索工作区数据。
RAG根据上传的报告，消费者最关注哪些需求？检索报告/评论原文；返回来源、页码/章节，以及适用时的语义相似度。

Module 06 - 职责分工与通信契约

A2A 连接服务，LangGraph 协调任务。

每个 Agent 都有独立镜像、进程、启动入口和沙箱
Agent负责什么输入 → 输出 / 边界
ChatUI/API、上传验证、写入私有 Blob、展示进度。浏览器请求 → Orchestrator A2A。跨 Agent 边界发送已登记的 FileRef，而非原始文件字节。
Orchestrator所有者/工作区校验、规划、分发/汇合、综合、图表、审核和运行持久化。问题或文件引用 → 类型化工作任务 → 有证据支撑的答案。图状态保留在本沙箱内。
Data Processing提取、推断表结构、分块有效文本、生成嵌入、提交摄取。经验证的 FileRef → 数据集/向量 + 计数、跳过记录与警告。
RAG限定工作区的余弦检索；按需提供有界评论概览。查询 + 过滤条件 → 最多五个证据片段、来源信息和覆盖范围警告。
SQL感知结构生成 SQL、AST 验证、工作区重写和受限执行。问题 + 数据目录 → 已执行 SELECT、列、结果行和行数。不允许修改数据。

先验证，再调度：配置的对等 URL → 经认证的 Agent Card → 校验角色、技能、A2A 1.0、流式支持和精确端点 → JSON-RPC/SSE。类型化产物返回结果，状态更新返回进度；对等服务不可达时显式报错，不回退到本地工作 Agent。

Module 06 - Azure 服务映射

复用基础设施，只补齐缺少的能力。

云端主路径：Bash / Bicep + 独立的 aca CLI
Azure 服务在方案中的作用复用 / Module 06 新增
ACA Sandboxes为五个独立 Agent 提供硬件隔离的运行环境。复用 Module-04 SandboxGroup 及其已有 VNet 连接；从 Agent 磁盘镜像创建五个沙箱。
Azure Container Registry为每个 Agent 构建并分发独立镜像。复用 Module-01 ACR；通过 ACR Tasks 云端构建，不需要本地 Docker。
Microsoft Foundry通用推理 / SQL 生成；摄取与检索所需的嵌入。复用账户、项目和通用模型；新增 text-embedding-3-small，默认 1536 维。
API Management使用 Entra 认证，治理 Responses 和 Embeddings 调用。保留已有 Responses 路由；在现有 /foundry API 下增加 POST /openai/v1/embeddings 和独立的账户级后端。
Blob Storage私有原始文件，独立于 Agent 计算生命周期保留。复用存储账户，仅创建私有 data 容器。只读挂载是额外的文件系统视图，不是上传通道。
HorizonDB / PostgreSQL Flexible Server共享 SQL + 向量存储，保存工作区、文档元数据、数据集、证据和已完成运行。二选一部署：默认 HorizonDB，PostgreSQL 为替代方案；使用同一仓储实现与迁移。
Entra ID / 托管身份为模型、Blob、数据库和镜像访问提供令牌。五个 Agent 复用 Module-01 UAMI；主部署使用 Entra 数据库认证。A2A 另用服务端对等密钥。

嵌入调用身份链：Agent UAMI → APIM 校验调用者 oid 和 ai.azure.com 受众 → APIM 已有的系统分配身份 → Foundry 账户端点。不会静默回退到直连模型端点。

Module 06 - 工作流程一 / 一次摄取，多次查询

保留原始文件，分别存储数字与语义。

报告 → 向量

按页/章节边界分块，默认 400 token、重叠 60 token，保留来源 ID 和溯源元数据。

销售 → SQL 表

规范化列名，基于全部行推断类型。纯财务数值行只保存为关系型数据，不生成嵌入。

评论 → 两者兼有

保留关系型行，为有效评论文本生成关联原行的嵌入。空白、过短或重复文本跳过并计数，不删除独立数据行。

幂等性：工作区 + 校验和防止重复提交数据集。摄取失败时回滚数据行/向量并将文档标记为失败；原始上传 Blob 可能保留，需要纳入保留与清理策略。

Module 06 - 交付、证据与运行边界

让结果可检查，不夸大平台能力。

数据与 SQL 防护

上传内容是不可信证据，不是指令。检索限定工作区；SQL AST 校验限制表和函数，并为物理表重写工作区过滤、施加行数限制和只读执行。

失败处理与持久化

明确暴露弱证据和部分工作 Agent 失败。安全读取最多重试一次，答案最多修订一次。已完成结果写入 agent_runs；中断的 LangGraph 工作流不会自动续跑。

研讨会不等于多租户

浏览器 API 免密，持有 Chat URL 的人均可访问部署内数据。稳定所有者种子仅保留在服务端，A2A 另用对等密钥。默认数据库防火墙允许所有 IPv4 来源，生产环境必须收紧访问。

前置检查→storage→models→database→config→images→aca

Bash 部署使用 aca，不是 az containerapp sandbox 或 Dynamic Sessions。协作服务默认禁用自动挂起。数据库/知识库可跨计算重启保留，但这不代表运行中工作流具备持久调度能力。

学习验收：上传数据 → 检查摄取计数 → 验证四种模式 → 检查引用与实际 SQL → 演示缺失数据/工作 Agent 异常的明确限制。实际验证 Azure 连通性与权限；仅生成清单或进程健康检查不等于端到端验收。
