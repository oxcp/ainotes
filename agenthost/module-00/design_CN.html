两类受众，不同的优先级

企业侧重信任，消费端侧重流畅体验。

B2B

企业 / 业务

面向内部团队和多租户平台的具名 Agent 实例。

  • 严格的租户与部门边界
  • Entra ID、RBAC、条件访问
  • 可审计性、专用网络、数据驻留
  • 可预测的容量和 SLA
安全 - 治理 - 可靠性
B2C

消费者 / 最终用户

面向用户、团队和试验环境的大量会话，通常持续时间较短。

  • 快速激活、运维简单
  • 用户级 Sandbox 隔离
  • 外部身份或 API 驱动的访问
  • 积极缩容到零、按使用量付费
成本 - 速度 - 简洁

关键技术考虑 - 有状态设计

先持久化，再安全休眠。

1

启动

解析 Agent ID，并从 Blob 加载其 JSON 状态。

2

执行

处理消息、工具及受治理的模型调用。

3

保存

每次变更后写入对话和工具状态。

4

空闲

逐出、暂停或缩容到零，无需最后一次刷盘。

5

恢复

直接从 Blob 最新的持久化版本恢复。

唯一事实来源： <AGENT_ID>.json 存储于启用版本控制的 Blob Cool 层，不使用独立的 Redis 热缓存。
