# 数据处理

> 🌐 语言 / Language: [English](data-processing.md) | **中文**

上传过程验证扩展名、MIME、文件名、大小和 Office ZIP 结构。
原始文件存储在 `data/<workspace UUID>/<file UUID>/original`，并附有 SHA-256 校验和。
处理前会重新验证已登记文件引用、工作区、存储字节和校验和。

- PDF：按页提取文本；加密/扫描 PDF 明确失败，未实现 OCR。
- DOCX：提取段落标题和表格文本，不编造页码。
- MD/TXT：保留段落边界和 Markdown 标题。
- JSON：对象数组转为关系型数据集，其他 JSON 转为可检索文本。
- CSV/XLSX：生成规范化的唯一列名、保留原始名称，并保守地基于全部行推断类型。
  类型包括整数、小数、货币、布尔值、ISO 日期/时间戳、分类和文本。
  有歧义的日期保持为文本。XLSX 支持一个有数据的工作表，公式使用缓存值。

数值财务行以关系型方式存储，绝不生成嵌入。
命名为 review/description/comment 的字段或长文本字段会生成嵌入，
并通过 `source_row_id` 关联到其数据集表。空白、过短和重复文本会跳过并计数。
即使跳过重复评论向量，不同行仍保留各自的关系型身份。

分块使用 cl100k_base token，默认为 400 个 token、重叠 60 个，并遵循提取出的段落/页边界。
Foundry 嵌入分批生成，摄取和查询使用同一部署及维度。
云端两条路径均调用 Module-06 在 Module-01 APIM 中部署的 `/foundry/openai/v1/embeddings`
操作，使用 `https://ai.azure.com/.default`；均不会静默回退到账户直连端点。
元数据保留文档 ID、通过 documents 关联获得的文件名、文档记录中的校验和/Blob URI、
页码/章节、语言（简单的中英文启发式判断）、行和业务字段。
不会自动删除 PDF 中重复的页眉/页脚，研讨会期间应检查来源质量。

摄取在一个数据库事务中提交。文档行锁和唯一约束 `(workspace_id,checksum)` 防止重复提交数据集。
失败时回滚行/向量并将文档标记为失败。
处理失败或重复提交后，原始 Blob 上传对象可能仍保留；保留策略清理必须考虑这些孤立原始文件。

语义 RAG 根据当前已完成文件清单规划有界检索，包括分片文件等来源组。
它在文档分块和评论向量上执行精确余弦检索，强制按工作区/来源过滤，
支持可选元数据谓词和相关性阈值；合并、去重后最多返回 `TOP_K` 个结果（默认五个）。
评分/情感条件作为元数据谓词执行，而不只是放入嵌入查询文本。
显式约束的纯元数据样本必须同时包含评分边界和情感标签；
它绕过相似度阈值，但仍保留工作区/来源/元数据过滤。

`review_overview` 则读取有界的已存评论片段，不进行语义检索，并报告截断情况。
片段计数和选取的样本都不能代表完整评论行数或情感分布；这些统计须对所选数据集执行 SQL。
全文/DiskANN 索引属于扩展功能，不是本研讨会有限规模数据集的必要条件。
相似度不等于相关性证明；最终审核会检查证据和相互冲突的陈述。
