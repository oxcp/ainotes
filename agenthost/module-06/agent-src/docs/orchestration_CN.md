# 编排

> 🌐 语言 / Language: [English](orchestration.md) | **中文**

类型化的 LangGraph 状态保存 ID、问题/近期上下文、文件引用、已验证计划、受限工作 Agent 结果、
错误、答案草稿、有界图表规格、审核结果和修订次数，绝不保存原始文件字节或完整文档。

| 节点 | 职责 |
|---|---|
| receive_request | 验证工作区存在 |
| classify_and_plan | 模型选择 DIRECT/RAG/SQL/HYBRID；服务端构建依赖计划 |
| direct_llm | 不检索数据的通用或创意回答 |
| process_uploaded_file | 运行确定性的摄取流程 |
| rag_search / sql_query | 独立工作 Agent；安全读取超时后可重试一次 |
| aggregate_results | 超步汇合；保留部分结果和明确的工作 Agent 错误 |
| generate_final_response | 综合事实、证据、解读和建议，生成完整答案 |
| prepare_charts | 构造有界图表数据源，按需提取带原文引用定位的文档数值，并验证所选图表 |
| review_evidence | 审核实际草稿、计算、引用、冲突和无依据陈述 |
| revise | 最多修订一次 |
| handle_error | 明确返回无法生成经过验证的答案 |
| emit_response | 完成运行 |

HYBRID 条件分支在同一个 LangGraph 超步中调度 RAG 和 SQL，两者在下一个超步进入汇总。
本地图事件屏障测试和远程 A2A 事件屏障测试覆盖此并行调度行为。
每个生产工作节点使用 A2A 客户端，LangGraph 状态保留在 Orchestrator 沙箱内部。
规划器接收问题、近期上下文及当前文件/数据集清单。Agent Card 用于校验配置好的对等服务，
不是供规划器动态发现的工具目录。
展示的 `tasks`/`depends_on` 计划描述固定图分支，不是任意可执行 DAG。

顺序设计说明：先生成再审核证据，让审核者检查实际答案，而不仅是来源材料。
修订后再次审核，第二次审核失败会阻止响应。
DIRECT 直接使用初次答案作为草稿，避免不必要的第二次生成调用。
`prepare_charts` 在生成和审核之间运行，或在文件处理后生成仅描述摄取的摘要图表。
数据源包括实际 SQL 行、摄取计数、RAG 数值元数据、带原文引用定位的文档数值，
以及当前用户请求中明确给出的前后百分比。文档图表由模型选择数字文本及出现位置，
服务端根据检索片段校验引用并读取数值，不接受编造数字，也不从丢失的 PDF 布局推断图表标签。
用户提供的对比会明确标注，不能冒充已独立验证的报告事实。
适用时，先进行文档提取，再判断是否有可绘图数据；
明确要求图表但没有可用数据时返回 `CHART_DATA_UNAVAILABLE`。
长表 SQL 可按 `series_column` 转为多系列；拒绝重复/不完整单元格，不用虚构的零补齐。
货币和比率系列不得共用柱状图/折线图的同一数值轴。
图表失败/超时记录为明确的部分失败错误，不丢失答案。审核通过 `chart_issues` 报告纯图表语义问题，
对应图表会被移除，但不会阻止有效文字。
规格限制为四张图，每图四个系列、40 行；完成的运行 JSON 和浏览器本地历史都会保留它们。
详见 [Chat 图表](../chat_agent/README_CN.md#聊天内图表)。

进度由实际节点和摄取阶段发出，通过一秒间隔的有界轮询获取，不使用假计时器。
限制为：24 个图步骤、一次安全读取重试、一次修订、四个活动工作流、
每次运行 100 个进度事件、`MAX_RUNS` 个内存运行记录（默认 200），以及可配置的请求/工作 Agent/查询超时。
不会重试 SQL 修改操作，因为根本不允许此类操作。

只有持久化成功后才暴露终态运行状态。完成结果保存到 agent_runs，
进程内存中不存在时会从数据库读取。部署验收应针对目标数据库验证这一重启行为；
尚未实现运行中的图检查点恢复。
Repository 的 `save_run`/`run` 边界是未来持久化调度器/检查点组件的持久化接口。
进程崩溃可能遗弃运行中的任务；重新上传已完成校验和对应的文件会复用处理记录。
不会将已停止的进程宣称为可恢复的工作流引擎。

Chat 的工作区/聊天/上传/运行操作跨越同一个 A2A 边界。
浏览器文件字节在 Chat 进程中进入私有 Blob；只有经过验证的 FileRef 传到 Orchestrator 和 Processing 服务。
Processing 的任务状态更新转发到 Orchestrator 的运行事件列表。
不可达的工作 Agent 返回 PEER_UNAVAILABLE，不会回退到进程内实现。
验收应验证停止 SQL 后的 HYBRID 部分成功/错误结果，保留可用 RAG 证据且不编造 SQL 结果。
每个服务的临时 A2A 任务使用受限的内存历史，它们不是持久化 LangGraph 检查点。
