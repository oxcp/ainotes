# 安全与运维

> 🌐 语言 / Language: [English](security.md) | **中文**

- Chat 浏览器 API 专为学员独立部署的 workshop 提供免密访问。任何能访问 Chat URL 的人
  都能列出/创建工作区、上传并查询该部署的数据；请勿上传敏感数据。
  工作区不再绑定由密钥派生的所有者；轮换对等凭据不会隐藏已有数据。
  生产共享使用时应添加经过验证的 Entra JWT 身份和逐用户所有权。
- 对外使用 HTTPS。本地服务器按文档绑定到环回地址。UI 仅支持同源，不开放宽松的 CORS。
- A2A 的发现和协作使用独立的对等 bearer 密钥，浏览器不会收到该密钥。
  卡片不能重定向配置的端点，也不能改变预期角色/能力。
  工作 Agent 拒绝不存在的工作区，并将文件/查询操作限定在所选工作区内。
  该共享密钥研讨会信任模型不是生产级逐 Agent/逐用户身份；
  多租户使用前应添加有作用域的凭据或经过验证的工作负载 JWT。
- 在受信任本地网络之外，沙箱间使用 TLS/mTLS。
  AKS 示例中的内部 HTTP 和共享 UAMI 是研讨会简化措施；
  NetworkPolicy 限制工作 Agent 入站流量，但不会加密它。
- ACA 的匿名 Chat 入口没有浏览器访问门槛；A2A 端点仍需对等 bearer 密钥。
  不要将镜像拉取托管身份等同于可用的来宾运行时身份，应单独配置和验证来宾凭据。
- 原始上传文件存储在私有存储中，但内容可通过公开的 workshop API 查询。
  Azure SDK 使用 DefaultAzureCredential 和 Storage Blob Data Contributor。
  不需要账户密钥、公共容器或 SAS URL。
- 所选数据库凭据来自通用 `DB_*` 环境变量；`DB_PROVIDER` 为 `horizondb`（默认）或 `postgresql`。
  Bash 云端主路径使用 `DB_AUTH_MODE=entra` 和 Module-01 UAMI，运行时不包含 `DB_PASSWORD`。
  管理员密码仍是受保护的预配输入。本地/显式密码模式部署仍需匹配的数据库密码，
  但不是云端主路径的认证方式。
  Azure 环境必须使用 TLS；
  配好信任存储后优先使用 `verify-full`。在需要时配置私有网络/DNS 连通性。
- SQL AST 只允许一条 SELECT（包括 SELECT CTE）、获准数据集表和少量安全函数允许列表。
  物理表包装在工作区谓词中。拒绝修改型 CTE、系统目录、INTO、锁、多语句、
  未批准函数和过多连接。数据库事务只读并设置语句超时。
- 研讨会使用一个数据库角色执行摄取和查询。只读事务保护查询路径；
  生产环境应采用分离的最小权限角色及数据库级 RLS，实现纵深防御。
- 将所有上传内容视为不可信提示数据。它不能设置工作区 ID 或选择任意数据库表。
  模型输出使用 Pydantic 结构，引用 ID 独立于模型审核者进行检查。
  单靠提示无法保证消除提示注入。
- 渲染使用文本节点，不允许用户控制 innerHTML。支持基础 Markdown 标题、段落和代码围栏；
  有意禁用原始 HTML 和自动外部链接。CSP 阻止外部脚本。
- 上传设置文件名、MIME、大小、压缩包条目和解压展开大小限制。
  压缩包只读取，不解压到磁盘。PDF 解析仍是资源敏感操作；
  生产中的不可信文件解析应放在隔离工作进程中。
- 日志记录 ID、阶段、计数、耗时和错误类别，不记录原始提示、SQL 数据、凭据或异常消息。
  证据持久化到经过授权的数据库，不输出到日志。
- 工作区记录、向量、运行证据和 sessionStorage 聊天历史可能包含敏感数据。
  请与客户确定保留策略。尚未实现自动保留清理或面向用户的删除 API。

## 清理

对于可丢弃的本地数据库，`docker compose down -v` 会删除该 Compose 项目的数据库卷。
停止应用后，只删除本模块的 `.local/data` 内容，不要删除共享 Blob 容器。
Azure 环境下，管理员应仅删除所选工作区的动态数据集表、评论/分块记录、数据集元数据、
运行和洞察，再删除文档记录，最后删除工作区。随后仅删除其 UUID 前缀下的 Blob 对象。
不要接受模型生成的清理查询。检查 Blob 软删除/版本保留和数据库备份：
逻辑删除不等于立即物理擦除。
